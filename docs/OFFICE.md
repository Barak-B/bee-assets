# מסך משרד, כרטיס לקוח ומפתחות אישיים

מה שהמשרד צריך כדי לנהל עבודות בלי לעלות על הגג: כל העבודות במקום אחד, איפה כל אחת עומדת, ומה דורש טלפון היום.

## איפה

`https://app.barak-e.com/office` — אותו פרויקט Pages ואותו אחסון כמו האפליקציה, בלי הגדרה נוספת. נכנסים עם **מפתח משרד או מנהל**. המפתח נשמר בדפדפן הזה בלבד ("יציאה" מוחק אותו).

## מה רואים

| חלק | מה יש בו |
|---|---|
| **מספרים** | עבודות פעילות · ממתינות לאישור (וסכומן) · אושרו ב-30 יום (וסכומן) · **דורשות טיפול** |
| **שלבים** | סקר → הצעה → נשלח ללקוח → הלקוח אישר → בהתקנה → נמסר. לחיצה מסננת |
| **טבלה** | פרויקט ולקוח (טלפון לחיץ), שלב והצעד הבא, הצעה אחרונה (סכום, kWp, "לאימות"), קישור (נפתח / טרם נפתח / אושר), דוחות (וכשל אם יש), סוקר, פעילות אחרונה |
| **חיפוש** | שם, לקוח, טלפון (בכל כתיב: `050-1234567` = `+972501234567`), כתובת, מספר הצעה |
| **פרטי עבודה** | לקוח (טלפון, וואטסאפ, מייל) · כל הקישורים שפורסמו (גם מבוטלים), צפיות, אישור הלקוח ואם ה-ת״ז אומתה · דוחות שטח ותוצאתם · פרטי הסקר ותמונות · **סטטוס משרד והערה** |

## עבודה חדשה מהמשרד ושיבוץ סוקר

**"+ עבודה חדשה"** במסך המשרד: לקוח, טלפון, כתובת (חובה), מייל, שם פרויקט, הערה לסוקר, סוקר ומועד סקר.

1. העבודה נפתחת בשלב **ממתין לסקר**.
2. הטלפון של הסוקר המשובץ מושך אותה בסנכרון הבא שלו: מיד ב"סנכרן לשרת", או תוך 10 דקות לכל היותר ברקע. מופיעה הודעה "עבודה חדשה מהמשרד".
3. בטלפון הסקר כבר ממולא: לקוח, טלפון, כתובת, מועד והערה. ברשימה רואים "ממתין לסקר · 📅 22.10".
4. מהרגע שהסוקר עובד עליה, עותק הטלפון הוא הסקר. המשרד ממשיך לנהל רק את השיבוץ, המועד, הסטטוס וההערה, שנשמרים בנפרד.
5. **שיבוץ מחדש:** בפרטי העבודה בוחרים סוקר אחר. הטלפון של הסוקר החדש מושך את העבודה בסנכרון הבא.

אפשר לשבץ רק מי שיש לו מפתח אישי פעיל, ולכן שובץ ב-`PUBLISH_KEY` לא קיים.

רק עבודה **פעילה** יורדת לטלפון. עבודה מוקפאת, לא רלוונטית או סגורה לא יורדת. סוקר שמחק אצלו עבודה שעדיין פעילה ומשובצת לו יקבל אותה שוב בסנכרון הבא. כדי שלא תחזור, מבטלים את השיבוץ או משנים את הסטטוס במשרד.

## איך נקבע השלב

**השלב לא מוזז ביד.** הוא נגזר ממה שקרה בפועל, באותו קוד בשרת ובאפליקציה (`apps/bee-solar-survey/src/stage.ts`):

| שלב | מתי |
|---|---|
| נמסר | דוח מסירה נעול |
| בהתקנה | יש דוח יומי / צ׳קליסט התקנה / בדיקת 62446 / ליקויים |
| הלקוח אישר | הלקוח אישר גרסה כלשהי בקישור (נשאר גם אם הקישור בוטל אחר כך) |
| נשלח ללקוח | יש קישור פעיל |
| הצעה | יש גרסת הצעה |
| סקר | נסקר (יש תמונות, או שהסקר מלא מספיק לתכנון), ועדיין אין הצעה |
| ממתין לסקר | עבודה שנפתחה ועדיין לא נסקרה בשטח |

מעל השלב המשרד מסמן **סטטוס**: פעיל / מוקפא / לא רלוונטי / סגור, עם הערה קצרה. הסטטוס נשמר בשרת בנפרד מהסקר, ולכן הטלפון לא דורס אותו. הוא חוזר לטלפון בסנכרון הבא ומופיע ליד הסקר ברשימה.

### "דורשות טיפול"

(`src/office/attention.ts` — הספים בראש הקובץ)

- עבודה חדשה בלי סוקר משובץ;
- משובצת בלי מועד סקר יומיים;
- מועד הסקר עבר ואין עדיין סקר;
- סקר בלי הצעה 3 ימים;
- קישור שהלקוח לא פתח יומיים — להתקשר;
- נפתח ולא אושר 5 ימים — לבדוק מה עוצר;
- אושר ועדיין אין דוח התקנה 14 יום.

עבודה מוקפאת / לא רלוונטית / סגורה לא נספרת.

## כרטיס לקוח בסקר

בטופס הסקר, אחרי "פרטים כלליים", יש פרק **לקוח**: שם, טלפון, מייל, ת״ז / ח״פ, סוג לקוח (פרטי / עסקי). הכול רשות, ואפשר להשלים אחרי הסקר. האפליקציה מזהירה ולא חוסמת: חסר שם, טלפון לא ישראלי, מייל לא תקין, ספרת ביקורת של ת״ז שגויה.

לאן זה זורם:

- **הצעה ו-PDF:** "לכבוד <שם>", ושם הלקוח בדף ההצעה אונליין.
- **וואטסאפ:** אחרי פרסום קישור יש כפתור **"וואטסאפ ל<שם>"**. הוא פותח את וואטסאפ עם המספר וההודעה מוכנה, והסוקר לוחץ שלח (Law #2: אין שליחה אוטומטית ללקוח).
- **אישור אונליין:** כשיש ת״ז בסקר, 4 הספרות שהלקוח מקליד חייבות להתאים להן:
  - אחרי 5 ניסיונות שגויים הקישור ננעל לאישור;
  - האישור נשמר עם "ת״ז אומתה";
  - בלי ת״ז בסקר כל 4 ספרות מתקבלות, והאישור מסומן "לא נבדקה".
  - הת״ז עצמה לא נשלחת לדף הלקוח. לשרת נשלחות רק 4 הספרות האחרונות, ליד ההצעה ולא בתוכה.
- **דוחות שטח:** שם הלקוח ממולא מהסקר.
- **רשימה ובמשרד:** שם וטלפון לחיץ, וחיפוש לפי טלפון.

## מפתחות אישיים ותפקידים

עד עכשיו היה מפתח אחד (`PUBLISH_KEY`) בכל הטלפונים. עכשיו:

| תפקיד | מה מותר |
|---|---|
| **סוקר** | גיבוי סקרים, תמונות, הצעות ודוחות, פרסום קישור ללקוח, שחזור לטלפון חדש |
| **משרד** | כל זה + מסך המשרד, סטטוס והערה, feed הכוורת (`/api/hive/jobs`) |
| **מנהל** | כל זה + יצירה וביטול של מפתחות |

- `PUBLISH_KEY` הוא **המפתח הראשי** (מנהל). הוא ממשיך לעבוד כמו קודם, ולכן שום דבר לא נשבר. עדיף שיישאר רק אצל ברק.
- **יצירה:** מסך משרד → "מפתחות" → שם + תפקיד → "צור מפתח". המפתח (`bee_…`) **מוצג פעם אחת**. מדביקים אותו בטלפון של הסוקר: מחירון → שרת החברה → מפתח.
- **טלפון אבד:** "בטל" ליד המפתח שלו. הטלפון הזה מפסיק לגבות ולפרסם מיד, וכל השאר ממשיכים לעבוד.
- **בשרת נשמר רק sha256 של המפתח** (`auth/keys/<sha256>`). רשימת המפתחות מראה שם, תפקיד, מי יצר ו-4 תווים אחרונים.
- **"בדיקת חיבור לשרת"** במסך המחירון אומרת עכשיו גם של מי המפתח ("המפתח תקין — דני (סוקר)").
- **מי עשה מה:** כל סקר שמגיע נרשם עם שם המפתח ששלח אותו (`receivedBy`), וכל קישור עם מי שפרסם (`published_by`).

## API (חדש)

| נתיב | תפקיד | מה |
|---|---|---|
| `GET /api/me` | כל מפתח | של מי המפתח |
| `GET /api/office/overview` | משרד | כל העבודות: שורת סקר + לקוח + `stage` + `office` + `latestQuote` + `links` (צפיות, אישור) + `reports` + `lastActivityAt` |
| `PUT /api/office/status/<surveyId>` | משרד | כל אחד מ-`{ status, note, assigned_to: <id מפתח>\|'', planned_date: YYYY-MM-DD\|'' }`. משתנה רק מה שנשלח |
| `POST /api/office/jobs` | משרד | עבודה חדשה: `{ customerName, customerPhone, address, customerEmail?, projectName?, note?, assigned_to?, planned_date? }` → `{ id, office }` |
| `GET /api/office/surveyors` | משרד | מי אפשר לשבץ: מפתחות פעילים (שמות בלבד) |
| `GET /api/office/keys` | מנהל | רשימת מפתחות (בלי המפתחות עצמם) |
| `POST /api/office/keys` | מנהל | `{ name, role }` → `{ key, row }`. המפתח מוחזר פעם אחת |
| `DELETE /api/office/keys/<id>` | מנהל | ביטול (נשמר לתיעוד) |

`GET /api/surveys` מחזיר לכל סקר את `office` ואת `assigned_to_me`, כלומר אם העבודה שובצה למפתח ששאל. כך הטלפון מושך את העבודות שלו.

`POST /api/quotes` מקבל עכשיו גם `survey_id` ו-`customer_id_last4`. שניהם פרטיים: נשמרים ליד ההצעה ולא בתוכה. `PUT /api/surveys/<id>` מחזיר את `office`, וכך הסטטוס מגיע לטלפון.

## אחסון ב-R2 (חדש)

```
auth/keys/<sha256>                  מפתח אישי (customMetadata: שם, תפקיד, נוצר, בוטל, 4 תווים אחרונים)
office/<surveyId>                   סטטוס משרד, הערה, סוקר משובץ ומועד סקר
quote-links/<surveyId>/<token>      כל קישור שפורסם לסקר (נשאר אחרי ביטול, עם revoked_at)
quotes/<token>/accept-fails.json    ניסיונות אישור עם ספרות שגויות
```
