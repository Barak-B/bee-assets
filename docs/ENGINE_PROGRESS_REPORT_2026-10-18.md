# מנוע התכנון bee-cad — דוח התקדמות וסיכום מקיף (18.10.2026)

**למי:** ברק ברזל, ברק הנדסת חשמל · **ענף:** `claude/jolly-pascal-bhkk0h` (PR #20, טיוטה) · **מצב:** גרסה מתקדמת לבדיקה

## 1. השורה התחתונה

מודל תכנון אחד (קובץ JSON) מייצר היום **סט תוכניות BESS מלא של 15 גיליונות A3** — שער, הערות כלליות, פריסת תשתיות, שלושה חד-קוויים, הארקות, תקשורת, ארבע חזיתות לוחות, שבלונת קידוח, רשימת כבלים וטבלת עומסים — כקובץ PDF אחד, מאורכב לתיקיית הלקוח, עם דוח בדיקה עצמית ורשומת משימה ל-Hive. כל 15 הגיליונות עוברים אודיט חפיפות טקסט נקי (0/0/0) ו-22 בדיקות אוטומטיות.

הדוגמה: **כל גדר (אפקון אגירה / Roche)** — 4 × Normal 261, לוח איסוף PV+BESS, לוח BESS עם PCS1–4, לוח תקשורת — כולה נבנתה מהסט G002 של Roche (28.09.26) ומדף הנתונים של REL261, כך שאפשר להשוות גיליון מול גיליון.

**מה לבדוק עכשיו (PDF מצורף):** `kal_gader_SET.pdf` — האם הפריסה, הסימונים והטבלאות נראים כמו שאתה רוצה להגיש ללקוח; והאם ההנחות המסומנות "לאימות" (ראו §5) נכונות.

## 3. איך מריצים (במשרד)

```bash
cd engine && pip install -e ".[dev]"
bee-cad check examples/kal_gader_bess.json                 # בדיקה עצמית בלבד
bee-cad render examples/kal_gader_bess.json --out out/kg --pdf \
   --archive "L:/האחסון שלי/עבודה/לקוחות חברות ומכרזים" --stage design --job auto
```

הפלט: `out/kg/kal_gader_SET.pdf` + גיליון-גיליון ב-`out/kg/sheets/`, DXF אחד עם כל הגיליונות, `kal_gader_qa.md`, `kal_gader_job.json`; והעתק מסודר ב-`…/אפקון אגירה/כל גדר — BESS + PV/05 תכנון/` (סט PDF, גיליונות/, CAD/, manifest.json). Google Drive Desktop מסנכרן את התיקייה — אין צורך לגעת בקבצי CAD.

## 5. הנחות מסומנות "לאימות" — צריך אותך

1. **REL261 / Normal 261 — מסגרת הבסיס**: התקבל מדריך ה-O&M של Rochex/Afcon (20260410) — 8 חריצים Ø18×10, M12, מסגרת 1064×1405; המידות נקראו מתמונה (955/220/125/1145) — לאימות מול DWG של היצרן לפני ייצור הקורות. החורים הפנימיים דורשים פרופיל רוחבי מרותך בין הקורות.
2. **קורת Double-T**: IPE 200 הונח לפי גובה 200 ב-G009 — אישור קונסטרוקטור לפרופיל ולעוגנים (Hilti HIT-HY 200-A + HAS-U M16, 32 עוגנים).
3. **חזית הארון 150 מ"מ מקצה המשטח** (BESS1 של אורי פלסט) — מול ה-DWG של G003 (יש בו מספרים 240/210/300/120/150 שלא פוענחו מה-PDF).
4. **הנחיות מינהל החשמל לאגירה (24.03.2021)** — המספרים (מפסק ≤ 3 מ', 1.2 מ' מתחת לדרך מילוט, 0.6 מ' מעבר) נלקחו מתקצירים; הקובץ חסום בסביבה הזו — אם תוריד אותו ל-`docs/plan/research/sources/`, אכניס בדיקה אוטומטית `BESS_DISCONNECT`.
5. **כבאות**: מרחק 3 מ' / רחבת היערכות — מדיווחי יועצים (NFPA 855 בהתאמה), לא מהוראה רשמית.
6. **טבלאות העמסה**: שיטה C בלבד, נחושת [נבדק מול ידע קודם], אלומיניום [לאימות]; זה סינון — דו"ח eplan קובע.
7. **לוחות Roche** — ארונות IP66 להעמדה חיצונית הוגדרו "על הטיח"; אם הם על מסגרת רצפתית, לעדכן `mounting: floor` וה-QA ישתוק.

## 7. מה הלאה (הצעה לסדר)

1. **תוואי על תצ"א (G003)** — תמונת רקע (אורתופוטו/תצ"א) + תוואי כבלים, אבני שפה, תעלות; זה הגיליון היחיד מסט Roche שעדיין חסר.
2. **ארון רצפתי רב-תאי** (T4P 1900×650 כמו ב-LV-AUX של מצפה שלם) בחזיתות הלוחות.
3. **בדיקת BESS_DISCONNECT ו-clearances** אחרי אימות המסמכים (§5.4–5.5).
4. **חיבור ל-Hive**: `edit.cad_render` ב-`platform/schema/loops.json`, הפעלה אוטומטית אחרי הצעת מחיר מאושרת (S03 → S06), העלאה ל-Drive כ-dispatch.
5. **AS-MADE**: אותו מודל עם `status: AS-MADE` ושינויים מסומנים — תיק מסירה (S08).
6. **PV תלת-ממדי** — נשאר בתור; דורש פריסת מודולים + גיאומטריית גג.
