# סקירת מערכת B.E.E — הצעות מחיר ודוחות (2026-10-13)

> **מטרה:** לעבור על כל מה שיש במאגר `Barak-B/bee-assets` ובדומיין, להבין למה הצעות המחיר והדוחות "לא עובדים", ולהציע סדר עבודה שלב-שלב.
> **שיטה:** קריאת כל הקוד ב-`main`, כל 16 הענפים המרוחקים וכל ה-PR-ים הפתוחים; הרצת `npm test` + `npm run build`; הרצת האפליקציה ב-Chromium ללא ממשק (Playwright), יצירת סקר, הפקת PDF וייצוא כוורת, ובדיקת ה-PDF שיצא.

## 3. למה ה-PDF (הדוח) לא עובד — ממצאים מההרצה

הרצתי את האפליקציה הבנויה ב-Chromium, מילאתי סקר מלא, הוספתי תמונת גג ולחצתי "PDF". התוצאה ב-`apps/bee-solar-survey/src/pdf.ts`:

| # | ממצא | השפעה | איפה |
|---|---|---|---|
| 1 | **כל שורת עברית מצוירת כתמונת PNG** (canvas 700×36 לכל שורה) כי ל-jsPDF אין גופן עברי | קובץ של **2 MB לעמוד טקסט אחד**; הטקסט לא ניתן לבחירה/חיפוש; מטושטש בהדפסה; לא מתאים כמסמך ללקוח | `pdf.ts:13-41` |
| 2 | **אין גלישת שורות** — הערות, תוואי כבילה וכתובת ארוכה נחתכים אחרי שורה אחת | מידע שטח הולך לאיבוד בדוח (ראיתי זאת בהרצה: ההערות נחתכו) | `pdf.ts:129` |
| 3 | **תמונות נמתחות** לרוחב מלא × 55 מ"מ קבוע, בלי לשמור יחס גובה-רוחב | צילומי לוח/גג מעוותים | `pdf.ts:158-160` |
| 4 | **שדות חסרים בדוח:** מספר מונה, "לכלול סוללה", שדות מותאמים, רשימת החוסרים (completeness), מספר עמוד, מזהה פרויקט/גרסה | הדוח לא משקף את הסקר במלואו | `pdf.ts:57-132` |
| 5 | **ההורדה היא `a.click()` על blob URL** — ב-iOS כאפליקציה מותקנת (Add to Home Screen) זה לעיתים קרובות לא עושה כלום, ואין הודעת שגיאה | **הסיבה הסבירה ביותר ש"הדוח לא עובד" בטלפון של הסוקר.** אותו דבר ב"ייצוא כוורת" וב"גיבוי" | `pdf.ts:183-190`, `hive.ts:174-181` |
| 6 | **אין service worker** — יש `manifest.json` אבל אין קאשינג; הגופן Heebo נטען מ-Google Fonts | בלי רשת באתר: האפליקציה לא נפתחת, וגם אם נפתחה — ה-canvas מצייר ב-Arial | `index.html`, `public/` |
| 7 | הסוגריים ב-"(Wave 54)" מתהפכים, `favicon.ico` מחזיר 404 | קוסמטי | |

מה כן עובד: הבדיקות (6/6), הבנייה, השמירה האוטומטית, ציון המוכנות, ייצוא ה-hive JSON (שלושת ה-jobs נוצרים נכון כשהסקר מלא, `requiresHumanPick: true` נשמר).

## 4. תוכנית שלב-שלב

הסדר נבחר לפי "ערך מהיר קודם": קודם מתקנים את מה שיש ונותנים לסוקר דוח אמיתי, אחר כך בונים הצעת מחיר מינימלית שעובדת **בלי** לחכות ל-M0–M2 של המנוע, ורק אז מרחיבים ל-CPQ המלא.

### שלב 0 — סדר במאגר (יום אחד)

1. למזג את #17 (תכנון) ו-#10 (BiDi); לסגור את #12–#14 ולמזג את #15; להחליט על #16.
2. להוסיף GitHub Actions: `npm ci && npm test && npm run build` על כל PR ב-`apps/*`.
3. לחבר Cloudflare Pages ל-`apps/bee-solar-survey` (Root/Build/Output כבר מתועדים ב-README) כדי שתהיה כתובת אחת לשטח.
4. להחליט גבול: המאגר הזה = נכסים + PWA לשטח + מודולים טהורים (TypeScript ללא שרת). השרת, Postgres וה-CPQ המלא = `bee-live`.

### שלב 1 — דוח סקר שעובד באמת (2–3 ימים)

1. **להחליף את מנוע ה-PDF**: במקום ציור שורות ל-PNG, לבנות **תבנית HTML RTL** של הדוח (אותו עיצוב כמו האפליקציה, גופן Heebo/Rubik מוטמע מקומית, `<bdi>` למספרים ואנגלית) ולהפיק PDF דרך `window.print()` עם CSS להדפסה. זה הפתרון היציב ביותר בטלפונים, הטקסט נשאר טקסט, והקובץ יורד מ-2 MB לכמה מאות KB. לגיבוי ללא-דפדפן-הדפסה: jsPDF עם גופן TTF מוטמע (`addFileToVFS`/`addFont`) — רק כ-fallback.
2. **גלישת שורות, יחס תמונות, שדות חסרים, מספרי עמודים, מזהה סקר + sha256 מקוצר** בכותרת התחתונה (כמו שמפרט 12 דורש להצעה).
3. **שיתוף במקום הורדה**: `navigator.share({ files })` (Web Share API) ל-PDF, ל-hive JSON ולגיבוי; fallback לפתיחה בלשונית חדשה כש-share לא זמין. זה פותר את בעיית iOS.
4. בדיקת E2E אחת ב-Playwright (כבר יש Chromium בסביבה) שמפיקה את הדוח ובודקת שהוא נפתח, שיש בו טקסט אמיתי ושגודלו סביר — כדי שזה לא יישבר שוב.

### שלב 2 — PWA אמיתית לשטח (1–2 ימים)

1. `vite-plugin-pwa` + service worker: קאשינג של האפליקציה והגופנים, עבודה אופליין מלאה, התקנה ב-Android.
2. גופנים מקומיים ב-`public/fonts` במקום Google Fonts.
3. `favicon.ico`, בדיקת `createImageBitmap` ב-Safari ישן (fallback ל-`<img>` + canvas).

### שלב 3 — הצעת מחיר ראשונית שעובדת ("quote-lite", 1–2 שבועות)

לא מחכים ל-Postgres ול-bee-live. בונים מודול TypeScript טהור במאגר הזה, שמאוחר יותר עובר כמו שהוא ל-`modules/quotes` ב-bee-live:

1. **`packages/quote-core`** — פונקציה אחת: `buildQuote(surveyPayload, catalog, rules) → QuoteVersion`.
   - קלט: ה-`DesignSuiteSitePayload` + `target` + `preferences` שהסקר כבר מייצר (kWp יעד, סוג גג, ממיר מועדף, סוללה, אורך כבל AC).
   - קטלוג: קובץ JSON ראשוני (10–20 פריטים: מודול, ממיר לכל מותג מהצי, קונסטרוקציה לפי סוג גג, כבלים למטר, לוח, עבודה לפי kWp, בודק, קונסטרוקטור, אגרות חח"י כ-passthrough) — לפי סכימת `Product` במפרט 12 §1.
   - ערכות: "מערכת X kWp על גג Y" → שורות; כללים מ-`docs/plan/rules/pricing-rules.json` (מרווח, מע"מ, הצמדה) עם כל `needs_owner_input` מסומן.
   - פלט: `QuoteVersion` JSON בלתי-משתנה (snapshot של מחירים + sha256), שלוש רמות (Essential/Recommended/Premium כמו בסקיל הישן) — אופציונלי.
   - **בדיקות זהב**: 2–3 הצעות אמיתיות מהעבר של ברק (מוסוות) → המודול חייב להגיע ל-±5% מהן. זה הכיול של המפרט (§19(1)).
2. **מסמך הצעה**: אותה תשתית HTML→PDF משלב 1, לפי `docs/plan/templates/quote-pdf-sections.md` (שער, 3 מספרים, מערכת, מחיר, תשלומים, אחריות, החרגות, תוקף). כל שורה שמקורה כלל `unverified` מסומנת "לאימות".
3. **כפתור בסקר**: "הצעה ראשונית" → מייצר `QuoteVersion` + PDF כ-**טיוטה בלבד** (`dispatch.draft`, `requiresHumanPick: true`, חוק #2). אין שליחה ללקוח מהאפליקציה.
4. כתב כמויות XLSX (ExcelJS, `rightToLeft`) לפי `boq-xlsx-layout.md` — אפשר כבר כאן, כי זו פונקציה טהורה על אותו `QuoteVersion`.

### שלב 4 — חיבור הסקר לשרת (M0-10)

> בוצע חלקית בלי לחכות ל-bee-live: סעיף 1 רץ על פרויקט ה-Pages שלנו (ראו `docs/SURVEY_SYNC.md`). כש-bee-live יהיה נגיש, הוא ימשוך מ-`/api/hive/jobs` או יחליף את האחסון. האפליקציה לא תצטרך שינוי.

1. במקום הורדת JSON: `POST /api/surveys` ל-bee-live עם ה-hive bundle; תור אופליין ב-IndexedDB ושליחה חוזרת.
2. קישור `customer.id` אמיתי (בחירת לקוח מרשימה מהשרת) במקום `[OPEN]`.
3. ה-`QuoteVersion` משלב 3 נשמר ב-Postgres (`WP-M2-01`) — המודול לא משתנה, רק האחסון.

### שלב 5 — CPQ מלא לפי מפרט 12 (M1–M2, ~39 ימי פיתוח לפי spec 16)

ייבוא מחירונים עם diff ואישור, ערכות פרמטריות, `services/docgen` (Chromium + Rubik), ROI (pvlib/PVGIS), שער אמון ל-WhatsApp/מייל, חוזה + חתימה, Morning. שלב 3 הופך מ-"lite" ל-מלא בלי לזרוק קוד.

### שלב 6 — שכבת דוחות אחידה (M5)

פורט דוחות השטח מ-`bee-build` (ביצוע יומי, סיור, ליקויים, בודק, מסירה) על **אותה** תשתית תבניות HTML→PDF של שלבים 1 ו-3: כותרת/כותרת תחתונה אחת, גופן אחד, `<bdi>`, מספר גרסה ו-hash. דוח אחד = תבנית אחת + נתונים, לא מנוע PDF לכל דוח.

## 5. מה צריך מברק כדי שההצעה תהיה אמיתית

> את כל זה אפשר להזין עכשיו לבד, באפליקציה, במסך "מחירון" — כולל ייבוא קובץ מחירון מהספק.

1. **מחירון ראשון** (ספק אחד, Excel/PDF) + מרווח רווח ברירת מחדל ותנאי תשלום.
   - **לתחזית החיסכון:** המסלול (מונה נטו / צריכה עצמית / הזנה) והתעריפים בתוקף. בלי אלה ההצעה יוצאת בלי עמוד חיסכון.
   - **נוסחים קבועים:** אחריות לכל רכיב, "לא כלול", "באחריות הלקוח".
2. **2–3 הצעות מחיר אמיתיות** שיצאו בעבר (אפשר מוסוות) — לכיול ולעיצוב "שייראה כמו שלנו".
3. **טקסטים קבועים**: אחריות, החרגות, תוקף הצעה, הערות חח"י.
4. **נוסח אישור הלקוח** — כרגע "אישור עקרוני, ההסכם ייחתם בנפרד". כדי שיהיה חתימה מחייבת צריך עו״ד (חוק חתימה אלקטרונית, ביטול עסקה מרחוק) וספק SMS ל-OTP.
5. **החלטה**: האם `quote-lite` חי במאגר הזה (מומלץ, כי bee-live לא נגיש לסוכנים בענן) או ישר ב-bee-live.
6. גישה ל-`BarakElectric/B.E.E` לסוכן, אם רוצים ששלבים 4–5 ייעשו מכאן.
